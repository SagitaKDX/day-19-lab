NB2: Hybrid Search & Reciprocal Rank Fusion (RRF)

GATE 2 · 25 PTS
Công thức RRF Chuẩn:
Score(d) = ∑ (1 / (k + rank_r(d)))   (k = 60)

Lưu ý: rank là 1-based (1, 2, 3...). Document đứng đầu có rank=1, mẫu số là 61.

Đánh giá trên 50 Golden Queries:

NB5: Filtered Search & Vực Thẳm Chọn Lọc (Selectivity Cliff)

ADVANCED · 10 PTS

1. Post-Filtering

Tìm top-K vector trước, rồi mới lọc theo metadata.

⚠️ Sập recall khi bộ lọc chọn lọc cao (≤ 4% dữ liệu).

2. Over-Fetch Ladder

Tăng top-K lên gấp 10-50 lần để bù đắp.

⚠️ Tốn RAM & tăng độ trễ truy vấn phi mã.

3. Filtered-ANN

Qdrant duyệt index trực tiếp trên tập hợp hợp lệ.

✅ Duy trì 100% Recall ở mọi mức độ chọn lọc!
💡 Bài học rút ra: Khi xây dựng hệ thống production, hãy luôn sử dụng payload index của Vector DB (Filtered HNSW) thay vì kéo vector thô về rồi tự dùng code Python để lọc!

Cảnh Báo Lỗi Sai

⚠️ 10 Bẫy Sai Lầm Phổ Biến Nhất Cần Tránh

10 Pitfalls
1. Rank 0-based trong RRF: Làm méo mó điểm số phần tử đứng đầu.
2. Đổi Model nhưng không Re-Index: Lệch số chiều vector làm crash Qdrant.
3. Target Encoding Leakage: Tính mean trên toàn tập gây ảo tưởng AUC.
4. Latest Join thay vì PIT Join: Mô hình học trước dữ liệu tương lai.
5. Quên Warm-up trước khi đo P99: Dính cold start spike vượt 50ms.
6. Semantic Cache rò rỉ Tenant: Thiếu tenant_id trong cache key.
7. Post-filtering trên tập lọc chặt: Gặp hiện tượng Selectivity Cliff.
8. Cố chạy Docker trên máy yếu: Tràn RAM swap thay vì dùng Lite mode.
9. Vibe-coding không review diff: Bỏ sót các bug tính toán ngầm.
10. Nộp repo Private lên LMS: Grader không tải được code -> 0 điểm.
